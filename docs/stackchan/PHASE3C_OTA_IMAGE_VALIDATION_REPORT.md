# Phase 3C OTA 镜像离线验证

来源：private full-backup 的 `ota_0`/`ota_1` slice；二进制始终留在本机私有目录，没有复制到 Git、ZIP 或聊天。工具为本机 ESP-IDF v5.5.4 环境中的官方 `esptool.py v4.12.0`，命令形式先由 `image_info --help` 确认，再使用 `image_info --version 2`。

## 两槽差异

```text
SAME_IMAGE=NO
OTA1_DIFFERENCE_DESCRIPTION=VALID_BUT_DIFFERENT_OLDER_FLAPPY_BIRD_APPLICATION
```

两份镜像都以 `0xE9` 开头、均有六个 segment、均通过官方 checksum 与 appended validation hash；差异来自项目、版本、IDF、segment 布局和 app descriptor，而不是简单的擦除区。`ota_1` header 的 Flash size 标记为 2MB，`ota_0` 为 16MB；这不会让本次官方 parser 报 invalid，但属于后续部署前必须复核的版本差异。

## fresh ota_1 头部核对

```text
OTA1_HEAD_OFFSET=0x510000
OTA1_HEAD_LENGTH=0x10000
OTA1_HEAD_BYTES_FRESH=65536
OTA1_HEAD_BYTES_FULL_SLICE=65536
OTA1_HEAD_DIFF_BYTES=0
OTA1_HEAD_FRESH_MATCH_FULL_BACKUP=YES
READBACK_RESET_SIDE_EFFECT=YES
```

头部 fresh read 的第一次串口传输出现短读，随后只做了一次有界的 115200 retry；retry 成功并产生上述 65536-byte 比较。原始 esptool 日志和二进制均为私有证据，不进入交付包。
